Who it's for

Experienced engineers moving into AI and agent engineering

Professional software engineers (3+ years), in particular mobile and multimedia engineers who already think in state machines, asynchronous pipelines, performance budgets and device constraints. Track 2 also serves tech leads and architects who will own agent strategy.

Android analogies run throughout (coroutines ↔ asyncio, lifecycles ↔ agent state), and an optional elective covers on-device agents.

Before week 1

  • Comfortable in one typed language (Kotlin, Java or C++) and basic Python syntax
  • High-school algebra, vectors and matrices, basic probability
  • Git, a terminal, HTTP/JSON APIs
  • Any 64-bit laptop with 8 GB RAM (16 GB recommended). No GPU for the core modules

Self-check: fetch JSON from a URL and validate two fields; say what a (4×8)·(8×3) matrix product produces. If either is hard, start with the optional week-0 Python bridge.

What you'll build

Three capstones, graded on the same rubric

Everyone builds C1. Then you build C2 (Track 1) or C3 (Track 2). Rubric: functionality 30%, engineering quality 20%, evaluation 20%, safety & governance 15%, documentation & demo 15%.

C1 · weeks 21–22

Kaveri, a bilingual customer-operations agent

A customer-operations agent for an Indian D2C retailer or fintech that answers policy questions (RAG with citations), checks order/payment status (mock UPI/ONDC tools via an MCP server), remembers customer preferences with consent, escalates refunds through human approval, and works in English plus Tamil or Hindi. Delivered as a FastAPI + Docker service with tracing and evaluation reports.

33-page booklet · Core

C2 · weeks 27–28

Niyam, a multi-agent regulatory-compliance RAG

A regulatory-compliance copilot over public RBI/SEBI circulars: planner, retriever, analyst and verifier agents; a LoRA-fine-tuned small router model; hybrid retrieval with re-ranking; full observability; load test; eval gates.

37-page booklet · Track 1

C3 · week 28

Kanakku, invoice-to-pay for an Indian SME

Invoice-to-pay for an Indian SME: email/WhatsApp intake, GST invoice extraction and validation, three-way match against a mock ERP, approval routing, exception handling by an agent, built with n8n/Make plus code where needed; delivered with an ROI model, risk register and governance pack.

37-page booklet · Track 2

India-first

Built around Indian languages, payments and law

Tamil and Hindi

Measure how script choice changes token counts and cost (Lab 12.1), handle Tanglish and Hinglish code-mixing (Lab 12.2), and build a bilingual retriever over an English–Tamil corpus (Module 5).

UPI and ONDC, on mocks

A mock UPI payment agent with a PSP sandbox state machine and idempotency (Lab 12.3), a Beckn/ONDC-style buyer agent (Lab 12.4), and an MCP server for a mock ONDC catalogue (Module 7). Never real payment rails.

DPDP Act 2023

Consent-aware memory with erasure (Module 8), PII redaction for Aadhaar- and PAN-like identifiers and a DPIA (Module 10), and a DPDP governance pack for Track 2.

Costs in ₹

Token economics in INR from Module 1, a containerised agent with a ₹ cost report (Module 11), and a Monte Carlo ROI model in rupees (T2B).

Honest caveat: the Tamil and Hindi text in the course was written without native-speaker review. Have it reviewed before you rely on it.

Labs on local models

Every lab runs offline on a laptop CPU

Labs run against a deterministic mock model, so results reproduce exactly, or a small Qwen2.5-Instruct model (0.5B, 1.5B or 3B, Q4_K_M) served by Ollama. A cloud API key is optional, and none was used to build the course. Each booklet's appendix carries the real run log.

Labs measure things, not just demo them: recall@k, MRR and nDCG for retrievers; schema validity on a 50-item invoice set; attack success rate on an injection canary suite; p50/p95 latency and throughput; ₹ per 1,000 requests.

What was not run

  • GPU-only items (QLoRA/bitsandbytes, vLLM, a real Kubernetes cluster) are documented and validated, not executed. The T1B fine-tune is a CPU LoRA on a 0.5B model.
  • No Android device or emulator: E1's Kotlin samples were not compiled.
  • Zapier, Make and enterprise agent platforms: recipes from official docs, no accounts.
  • Datasets are synthetic and evaluation sets are small (tens of items).

FAQ

Questions

Do I need a GPU or a paid API key?

No. Core modules run on a CPU with a mock backend or a local Ollama model. Track 1's QLoRA and vLLM steps need a GPU; they are documented, and the course's own fine-tune ran as a CPU LoRA.

What will it cost to run the labs?

Nothing, if you stay on mocks and local models. The syllabus estimates that using a cloud model only for final evaluations keeps total API spend for the programme under ₹3,000; Track 1 GPU time is the main extra cost.

How long does it take?

30 weeks at 10–12 hours a week, about 330 hours: roughly 2 h reading, 1 h quiz and review, 6–8 h labs and projects, and 1 h discussion each week.

Which track should I pick?

Track 1 (advanced LangGraph, agent SDKs, LoRA fine-tuning and serving, then the Niyam capstone) if you want to build agent systems. Track 2 (n8n and no-code automation, enterprise platforms, ROI and governance, then the Kanakku capstone) if you will own agent strategy.

Is the course affiliated with a university or certificate provider?

No. It is an independent course. Its scope was benchmarked against a publicly available programme syllabus, but there is no affiliation, endorsement or partnership, and its certificate is not an accredited award.

What will the student portal include?

The student portal is coming soon. It is planned to give access to all 23 PDF booklets in your browser, the lab code archive, auto-graded module quizzes taken from the booklets' answer keys, progress tracking for every section and lab, and a place to save your capstone links and notes.

Are the Tamil and Hindi materials reviewed?

Not yet. They were written without native-speaker review, and the course says so. Treat any Indic-language score as provisional until reviewed.

Which tool versions does it use?

Versions were verified on PyPI and official docs on 11 October 2026 (LangGraph and LangChain re-checked 26 October 2026), e.g. LangGraph 1.2.17, LangChain 1.4.7, MCP spec revision 2026-07-28, FastAPI 0.143.0 and Ollama 0.40.3. They will drift; each module pins its own requirements.
